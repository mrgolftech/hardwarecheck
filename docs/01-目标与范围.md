# 01. 项目目标与范围（V0.1）

更新：2026-10-22；状态：规划基线，目标及指标均待项目内评审确认。

## 1. 背景与问题

硬件设计评审依赖工程师经验与检查要素表。当前可能存在：检查动作重复、器件手册查阅耗时、复杂跨页网络难以追踪、PCB 与原理图/需求核对分散、历史质量问题难以自动复用等痛点。**以上是待通过部门调研与基线采集验证的假设，不应直接作为已发生的事实或量化结论。**

本项目立足已使用的 Cadence OrCAD Capture 和 Allegro PCB Designer，不改变现有EDA设计流程、不要求迁移KiCad。

## 2. 总体目标

建立“专业知识结构化—专业工具可执行—Agent组织审查—工程证据可验证—人工确认闭环”的硬件设计智能审查能力体系，逐步用于原理图、器件/BOM、PCB和变更审查，提升质量风险前移识别能力与评审效率。

在职级晋升/成果申报场景，重点呈现：
- **硬件专业贡献**：面向实际问题抽象设计规则、拓扑约束、检查依据与判定边界。
- **体系建设贡献**：建立规则治理、工具链、样本集、可追溯报告和复用流程。
- **组织应用贡献**：推动跨项目/跨人员试点，通过可复核数据评估质量与效率收益。

## 3. 项目原则

1. **通用 Agent，不重造通用框架**：初期优先 OpenCode 等支持 Skills/脚本工具的平台，兼容其他Agent靠接口抽象实现；不开发独立GUI作为先决条件。
2. **确定性事实优先**：电路连接、元器件属性、公式与空间几何由脚本求解；LLM负责任务理解、上下文筛选、假设推理和报告。
3. **证据约束**：问题必须关联真实位号/网络/引脚、需求或手册版本/页码/条件；证据不足不能判为通过或确定错误。
4. **人工最终负责**：无法替代ERC/DRC、专家审核、SI/PI/EMC仿真及实测。
5. **数据安全**：设计数据在获批环境分析；未经授权不提交公开仓库或云端模型。
6. **先评测，后推广**：优先真实样本、已知问题和正常样本的客观回测。

|---|---|---|---|

## 5. 明确不做

- 不开发通用Agent底层、通用知识库平台或聊天GUI作为首期主要任务；
- 不重做EDA已经具备的ERC/DRC基础规则，除非为自动编排/统一报告调用；
- 不承诺“自动保证设计正确”“取代专家签署”“自动预测投板成功率”；
- 不基于只有网表的数据声称确认器件真实工作电压、PCB信号完整性或热裕量；
- 不自动改写原理图和PCB；任何未来写入能力需要备份、预览、差异确认与授权；
- 不将回归测试数量当成真实工程缺陷检出率。

## 6. 责任划分建议

| 角色 | 责任 |
|---|---|
| 硬件技术负责人 | 主导审查要素分类、规则判定边界、样本选择、最终技术验收 |
| 软/AI开发支持 | EDA适配工具、规则执行器、Skill工具接口、自动化测试 |
| 硬件专业工程师 | 提供经批准的样本，核实问题真值、提出反例与误报原因 |
| 质量/流程人员（按需） | 评审流程对接、质量问题闭环、推广机制 |
| 保密/信息安全管理 | 数据分级、模型接入、开源依赖与软件合规评估 |

## 7. 预期可交付成果

- 专业Skills / AGENTS工作方法；
- OrCAD/Allegro结构化适配工具（已完成部分必须有验证记录）；
- 检查规则库、规则结构化规范、版本管理机制；
- 审查证据和报告格式；
- 测试样本及基线、回归脚本和人工复核记录；
- 技术方案与应用评估报告，晋升答辩可使用的脱敏演示案例。

所有交付内容以验收记录和实际提交为准，规划不构成完成承诺。
