# 07. 第一版代码架构与运行指南（V0.2-alpha）

## 定位与交付形态

这是一套**通用Agent可调用的本地硬件分析工具**，不是完整商业EDA校验器，也没有自研GUI/Agent框架。所有工程数据默认保留在操作者授权的本地目录中；CLI不调用任何LLM API、外网、OCR或第三方EDA应用。

- **Agent层**：`.agents/skills/*/SKILL.md` 被支持Agent Skills格式的 OpenCode、Codex 等识别并按需加载。
- **专业执行层**：`src/hardwarecheck/*.py` 提供可重现、只读、JSON输出的查询与初步规则。
- **规则层**：`rules/catalog.json` 声明哪些检查已实现、哪些仍是规划；`templates/rule-example.yaml` 为工程规则设计示例。
- **验证层**：`tests/` 中的完全合成数据与单元测试，GitHub Actions可做不含客户数据的自动回归。
- **真实工程适配**：Seeed Schematic Analyzer、Allegro IPC-2581/SKILL工具不作为本仓库内已部署依赖，需独立按实际版本测试。

```text

```

## 安装（Python 3.10+）

在仓库根目录运行：

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install -e .
.venv\Scripts\python -m unittest discover -s tests -v
```

Linux/macOS可用 `python3 -m venv .venv`，激活后运行 `python -m pip install -e .`。

```powershell
hardwarecheck inspect --netlist tests/fixtures/pstxnet.dat --parts tests/fixtures/pstxprt.dat
```

使用真实网表时将参数换为本地的已授权路径，不要将文件复制到本公开Git仓库。

PDF额外需要：
```powershell

hardwarecheck pdf-search --pdf "C:\ApprovedWork\MPN_datasheet.pdf" --term "VIL"
```

**PDF命中 ≠ 已验证电气参数**。真实审查还要对MPN、修订版本、最小/典型/最大、测试条件及图表人工核对。

## 如何在通用Agent中使用

在安装好CLI的电脑上以该仓库作为工作目录启动OpenCode或支持Agent Skills的客户端。软件应能发现 `.agents/skills/` 下7项技能。可以先输入：

> 使用schematic-review Skill，对 `tests/fixtures/pstxnet.dat` 和 `tests/fixtures/pstxprt.dat` 做结构查询；逐项说明哪些是网表事实、哪些只是设计风险假设，不要声称通过了全板审查。

工程使用须先明确模型数据边界：CLI不联网，但是Agent是否把CLI输出（包括企业位号/网络等）发往外部模型，取决于模型接入与会话配置。**保密场景仅使用获批准的模型和执行环境。**

## 规则与状态约定

- `FAIL`：结构性冲突/定义明确的违反，仍需人工排除解析差错；
- `SUSPECTED`：启发式疑点（例如单成员网络）；
- `NEEDS_REVIEW`：网表/BOM清单差异等待设计变体解释；
- `INSUFFICIENT_EVIDENCE`：计划规则缺少必要输入，不能执行；
- `NOT_APPLICABLE` / `ERROR`：不适用/执行失败。
- `PASS`：只能代表已执行具体规则中的通过；不是设计整体合格。

当前第一版没有完整规则调度器，`rules.py` 固定执行已实现的少量规则；`catalog.json` 不代表所有声明的规则已投入执行。

## 完成度核对

用 `docs/PROGRESS.md` 记录实际提交、单元测试和真实EDA样本验证状态。任何人完成新能力，应增加测试、受限数据验证记录、结果边界说明，再修改进度，不得直接删除限制条款。
