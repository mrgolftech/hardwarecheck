# 04. 实施路线、试验设计和验收标准（V0.1）

> 全部阶段为**计划**，不是已完成成果；时间是粗估，视真实网表、EDA版本、数据质量和人员投入调整。先证明可靠性，再扩大范围。

## 1. 项目路径

| 阶段 | 建议节奏 | 优先事项 | 可复核交付物 | 进入下阶段的条件 |
|---|---|---|---|---|
| P0 解析可行性 | 约1–2周 | Seeed OrCAD Skill、原始网表、XML兼容性验证；BOM关联样例 | 解析日志、字段覆盖矩阵、人工对照样本 | 关键网络/引脚核对一致，未知/异常均可报告 |
| P1 原理图审查POC | 约3–6周 | 原理图规则分类、首批10–20规则、电源/复位/UART专项 | Skill、只读查询工具、规则文件、审查报告、回归测试 | 存在独立真值与可复核报告，误报/漏报已统计 |
| P2 PCB验证 | 约3–6周 | Allegro IPC-2581 与SKILL能力评估、局部几何与一致性检查 | PCB数据契约、已验证检查器、受控样例 | 不完整的PCB导出不会错误输出合格 |
| P3 部门试点 | 取决于实际项目 | 设计变更、跨域核对、规则治理、培训推广 | 项目使用记录、对照分析、评审闭环与改进计划 | 由部门确定推广门槛与验收职责 |

阶段可以重叠，但**不可把尚未验证的场景写成实现完成**。

## 2. 第一个最小闭环（推荐）

1. 选择一套取得使用授权的OrCAD设计（最好包含电源管理、复位、UART）；实际工程数据不上传此公开仓库。
2. 用官方导出文件 `pstxnet.dat`、`pstxprt.dat`，若能提供同步 Capture XML 更好；记录导出版本。
3. 用 Seeed Schematic Analyzer 测试 `overview / query component / query net`，核对原理图上人工标注的位号、管脚、网名及层次路径。
4. 对原理图检查要素表进行五类分类：结构确定型、计算验证型、器件知识型、跨域型、人工专家型。
5. 只选10–20条有明确定义且可获得数据的规则；每条都有适用前置、数据要求、通过/失败/不足状态。
6. 运行同一数据集的基线对照：`LLM-only`（只读可授权摘要）/ `工具-only` / `工具+Skill+Agent`。避免模型随意读取整份敏感网表。
7. 输出结构化检查结果；请独立硬件专家核对并记录反例。

**建议首批规则**：非固定输出稳压器反馈电压计算、输入/输出电压额定值、特定接口电平兼容性、I²C上拉存在性及供电域、规定配置脚状态、复位信号方向与时序前提、已定义的未接引脚规则、BOM位号/型号映射及其差异。这只是候选；并非所有规则都能仅靠网表完成。

## 3. 数据真值与样本设计

至少包含三个独立样本集合：

- **真实历史缺陷**：拥有修复前后文件、问题原因、工程师确认；若有保密限制在内部环境保存。
- **受控缺陷注入**：在脱敏/自研可公开样例上修改网络、阻值、器件/电压域等，记录注入变更，不把“故意损坏”当成生产问题。
- **正常设计负样本**：经专家在检查范围内确认符合相关规则，检验误报与过度推理。

**禁止**让Agent自己编造故障后又自行给出正确答案作为主要准确率证据。评测集应按规则和电路类型分层，尽可能避免提示词/规则设计时看过相同评测样本，记录模型、Skill、工具版本。

## 4. 量化指标定义

| 指标 | 计算方式 / 记录维度 | 解释 |
|---|---|---|
| 解析连接一致率 | 人工金标准中正确还原的 (位号,引脚,网络) 三元组 / 金标准三元组 | 分层记录，不以网络数接近替代 |
| 规则可执行率 | 在选定适用规则中能实际完成数据检查的规则数 / 适用规则数 | 缺失数据不计作已检查 |
| 已知缺陷召回率 | 检出的真缺陷数 / 已知真缺陷数（TP/(TP+FN)） | 需定义匹配标准和严重度 |
| 有效告警率（Precision） | 专家确认的有效告警数 / 系统总告警数（TP/(TP+FP)） | 疑似与确定性分类统计 |
| 误报负担 | 每份设计每100条适用规则的FP数，及人工处理时间 | 不能只用总告警数衡量 |
| 证据可追溯率 | 达到规则/设计对象/手册或计算证据要求的结论 / 相应结论总数 | 无证据者须隔离 |
| 检查工时变化 | 同一范围、复杂度可比设计的人工作业时长对照 | 记录人工复核AI结果的时间 |
| 高风险漏报清单 | 每个高风险已知缺陷是否命中及原因 | 不可用总体平均掩盖严重漏检 |

没有数据前不填写“提升30%”“准确率95%”等宣传指标。阶段目标和正式质量门槛由硬件负责人依据样本风险、工程成本和部门要求确定。

### 测试记录格式建议

| 设计/样本ID | 规则ID | 真值标签 | 模型/Skill/工具版本 | 系统状态 | 专家结论 | TP/FP/FN/TN | 证据链接 | 复核耗时 |
|---|---|---|---|---|---|---|---|---|

对于规则不适用或证据不足，单独计数；不轻易计入TN/TP。多次模型运行时统计结果波动，不只展示最好的一次。

## 5. 工程验收清单

### P0：适配
- [ ] 样本授权、涉密分级与使用位置已确认
- [ ] 原始导出工具及版本已登记
- [ ] 数据文件hash及解析日志已记录
- [ ] 典型位号/引脚/网络/层次路径与原图一致
- [ ] 异常解析对象可追踪而不是静默丢弃

### P1：原理图智能审查
- [ ] 首批规则按统一Schema入库并有负责人
- [ ] 每条规则提供正例、反例和缺失数据样例
- [ ] 检查状态能覆盖PASS/FAIL/SUSPECTED/NEEDS_REVIEW/INSUFFICIENT_EVIDENCE/NOT_APPLICABLE/ERROR
- [ ] AI引用全部经过网表/手册/计算来源核查
- [ ] 报告可标记工程师复核与最终处理意见
- [ ] 生成可复现的评测日志与版本信息

### P2：PCB专项
- [ ] IPC-2581导出所含对象及单位经过清点
- [ ] SKILL/IPC解析几何与Allegro原图抽查一致
- [ ] 网络映射与BOM位号差异可以显式报告
- [ ] 无条件输出SI/PI/EMC定量合格结论的行为已禁止

### P3：推广
- [ ] 试点工程/检查范围/人工基线一致
- [ ] 误报与严重漏报复盘
- [ ] 规则变更纳入评审与回归流程
- [ ] 应用效果报告明确统计口径、限制与下一步

## 6. 答辩成果证据准备

答辩以“组织能力提升”而非“自建聊天客户端”为主线：技术难题→专业方法→受控对照实验→真实缺陷→规则资产沉淀→实际推广。每个性能或收益数字必须能追溯测试记录，不以外部厂商发布值替代本单位效果。
