# 06. P0 首次验证操作指南（V0.1）

## 目标

仅验证一件事：**能否从当前OrCAD实际导出数据准确取得器件、引脚、网络的工程事实，并由通用Agent按需查询。**

不要求先完成全套AI规则、不要求安装GUI、不先承诺PCB功能。

## 前置条件

- 已获批准可用于测试的原理图设计，最好同时具备几组人工已知连接关系。
- OrCAD导出的 `pstxnet.dat`、`pstxprt.dat`；如可获取再加 `pstchip.dat`、Capture XML。
- 可在本地运行Python的Windows测试环境；用于AI调用的模型接口需符合单位数据安全规定。
- 独立的工程师/项目负责人事先抽选若干金标准 (位号,物理引脚,网络) 对照记录。

## P0 分步执行

1. **清点和备份**：记录文件名、文件类型、SHA-256、导出工具版本、数据归属和可公开性。测试数据不要放到公开仓库中。
2. **格式验证**：阅读 [Seeed Schematic Analyzer README](https://github.com/Seeed-Studio/ai-skills/blob/main/skills/schematic-analyzer/README.md)，按当前仓库版本安装依赖、运行项目自带的overview与位号/网络查询CLI。
3. **单点核验**：对预先固定的位号/引脚/网络样本，人工逐项核对查询结果；特别检查层次化网络、隐藏电源引脚、多单元器件和网络别名。
4. **DAT-only试验**：如没有Capture XML，记录缺失字段和工具实际行为；可参照 [Cadence Netlist Formatter](https://github.com/yuravg/cadence_netlist_format) 做轻量网络查询，不把“可查询网络”误认为“已恢复图纸层次”。
5. **BOM合并试验**：用一份允许使用的BOM映射位号、MPN、数值/封装，单独输出未匹配与歧义项，禁止自动套用错误型号。
6. **Agent小范围试验**：让Agent只通过只读查询工具回答预定工程问题，如“Uxx 的某引脚连接哪条网、同网上还有什么”。把输出同人工真值比较。
7. **生成P0报告**：输出解析器和输入版本、样本清单、通过/失败/未覆盖情况，给出下一步是否可进入规则建设的结论。

## P0出口判据

- 查询结果可与原始网表、原理图或独立真值对应；
- 错误解析和字段缺失能够被记录并定位；
- 对层次路径、网络别名、物理/逻辑引脚等重要场景有清晰支持范围；
- 测试过程能重复，所有代码和输入版本可查；
- 对未验证的功能明确列为待办。

若出现错误脚位映射或网络误合并，必须优先修复解析层，不能让LLM以自然语言“补救”工程事实。
