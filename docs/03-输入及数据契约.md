# 03. 输入资料、适配与数据契约（V0.1）

**文档性质：设计草案，不代表已有解析器实现或格式覆盖能力。**

## 1. 标准输入包建议

```text
<local-workspace-outside-public-repo>/
  design-A/
    schematic/
      pstxnet.dat
      pstxprt.dat
      pstchip.dat           # 视导出设置，非所有流程必需
      capture.xml           # 可选；用于Seeed完整OrCAD模式
    bom/
      bom.xlsx              # 或CSV
    datasheets/
      <MPN>_datasheet.pdf
    pcb/
      board.brd             # 在受控本地留存；不要求Agent直接读二进制
      board_ipc2581.xml     # 导出内容受Allegro配置影响
      exportJson.json       # 若使用对应SKILL脚本
    requirements/
      requirements.pdf
    reports/
```

本公开仓库只能放脱敏/公开的模拟样例。不要将真实公司工程文件放在仓库工作树中再指望单靠 `.gitignore` 防止外泄；在仓库之外管理实际工作数据。

## 2. 原理图逻辑数据

优先研究 Seeed [Schematic Analyzer](https://github.com/Seeed-Studio/ai-skills/tree/main/skills/schematic-analyzer)。其公开文档要求 Cadence 模式提供 `pstxnet.dat + pstxprt.dat + Capture XML`，网表负责精确连通、XML补充页面/属性。仅有DAT时，使用轻量解析方案先验证可获得字段；不假设页面坐标或图形排版存在。

解析后需保留：
- `refdes`、器件属性、MPN（来自BOM或原理图）、多单元器件信息；
- 原始网络名、别名、层次路径与内部ID；
- 元件引脚号、物理封装脚位、逻辑符号脚位的映射；
- 来源文件/行号（可获得时）、解析器版本；
- 无法解析或发生冲突的对象清单。

**验收原则**：至少对典型多页、隐藏电源引脚、多门器件、网络别名和接口连接设计建立人工真值样本，核对位号/引脚/网络映射；不能仅比较网络总数。

## 3. PCB布局布线数据

Allegro推荐优先尝试 `File → Export → IPC2581` 导出制造设计XML，而非假设 `.brd` 可直接由通用解析库完整解释。

注意Allegro另一处 `Setup → Cross-section → Export → IPC-2581` 可以导出**层叠数据**，不能视为已经导出了所有布线几何。导出时需记录：
- Allegro版本/功能授权、IPC-2581版本、功能模式、导出开关与层映射；
- 单位、坐标原点/旋转、板框；
- 层叠、元器件、焊盘、网络、走线、过孔、覆铜实际覆盖项；
- 导出网络名与原理图网络的对应关系；
- 导出日志与任何被省略的数据类别。

候选补充路径：[Allegro exportJson](https://github.com/juulsA/exportJson)。其原始JSON以 InteractiveHtmlBom 为目标，**不应假定拥有高完整度的铜皮/阻抗/回流数据**。

## 4. BOM规范化字段

| 标准字段 | 示例（虚构） | 规则 |
|---|---|---|
| refdes | U12 | 稳定唯一位号；多条位号按列表展开 |
| mpn | EXAMPLE-LDO | 区分实际制造商型号与公司内部物料号 |
| value | 10k | 保留原文及正规化值与单位 |
| footprint | QFN-16 | 与原理图/PCB封装映射交叉检查 |
| quantity | 1 | 与实际位号数量核对 |
| manufacturer | ExampleCorp | 作为型号歧义辅助字段 |
| variant | DEFAULT | 装配变体不可默认为同一配置 |
| populated | true | DNP器件与不装配变体需特别处理 |

## 5. 统一设计模型（提议的最小结构）

```json
{
  "schema_version": "0.1-draft",
  "design_id": "DEMO-001",
  "inputs": [
    {"kind":"orcad_netlist","path":"schematic/pstxnet.dat","sha256":"<computed-at-runtime>"},
    {"kind":"bom","path":"bom/bom.csv","sha256":"<computed-at-runtime>"}
  ],
  "components": [
    {
      "refdes":"U12",
      "mpn":"EXAMPLE-LDO",
      "pins":[
        {"number":"1","name":"VIN","net_id":"NET_5V"},
        {"number":"5","name":"OUT","net_id":"NET_3V3"}
      ],
      "provenance":{"source":"schematic/pstxnet.dat","locator":"to-be-defined"}
    }
  ],
  "nets":[
    {
      "id":"NET_3V3",
      "aliases":["+3V3"],
      "members":[{"refdes":"U12","pin":"5"}]
    }
  ],
  "warnings": []
}
```

以上均为虚构示意字段。真实实现须明确原理图网络多层命名/元件重复定义、引脚映射、器件装配变体、缺失值等边界。所有规范化行为保留原始数据与来源。

## 6. 手册参数契约

```json
{
  "mpn": "EXAMPLE-LDO",
  "datasheet_id": "EXAMPLE-LDO-revA",
  "parameter": "feedback_reference_voltage",
  "value": 0.8,
  "unit": "V",
  "statistic": "typ",
  "conditions": "VIN=5V, T=25C",
  "page": 12,
  "section": "Electrical Characteristics",
  "source_quote": "<verified-short-excerpt>",
  "verified_by": "human_or_extraction_validation"
}
```

一个PDF文本命中不等于参数语义正确；需要对版本、型号后缀、测试条件、典型/最小/最大、脚注、单位和表格列进行复核。重要参数未核实则返回 `INSUFFICIENT_EVIDENCE`。

## 7. 审查结果契约

```json
{
  "finding_id": "SCH-PWR-001:U12:1",
  "rule_id": "SCH-PWR-001",
  "rule_version": "0.1-draft",
  "status": "SUSPECTED",
  "severity": "high",
  "scope": {"components":["U12","R36","R37"],"nets":["NET_FB"]},
  "statement": "示例：反馈拓扑需要进一步验证",
  "evidence": [
    {"kind":"netlist","object":"U12.FB","source":"pstxnet.dat"},
    {"kind":"datasheet","mpn":"EXAMPLE-LDO","page":12}
  ],
  "calculation": null,
  "missing_inputs": ["verified resistor values"],
  "reviewer_decision": "unreviewed",
  "agent_provenance": {
    "model": "record-at-runtime",
    "skill_revision": "record-at-runtime"
  }
}
```

强制区分：`status`（系统检查状态）、`severity`（工程风险等级）与 `reviewer_decision`（独立人工结论）。对无法核实的模型引用执行隔离，不能转为确定问题。

## 8. 能力矩阵与缺失数据行为

| 可获得数据 | 支持的检查 | 不能据此给出的结论 |
|---|---|---|
| DAT网表 | 网络拓扑、位号/引脚基本关系（依具体解析能力） | 实际PCB去耦距离、波形、信号完整性 |
| DAT + XML + BOM | 器件参数映射、页面/模块属性、BOM差异 | 电气裕量全部合格 |
| 再加Datasheet与需求 | 适用场景下电平/电源/接口参数核对 | 无仿真的定量SI/PI/EMC合格 |
| 再加IPC-2581/PCB属性 | 布局几何、连通、部分跨域一致性 | 全部阻抗/串扰/热设计有效性 |
| 再加测试/仿真/约束 | 进一步核对设计目标与工程证据 | 替代正式审核签署 |

当关键字段缺失：输出明确的规则ID、缺失字段、受影响结论和建议补充文件；禁止自填不存在的网络或使用所谓“行业典型值”代替硬性门限。
