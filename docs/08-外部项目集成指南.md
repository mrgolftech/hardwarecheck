# 08. 成熟项目借鉴与适配路线（V0.2-alpha）

## 不盲目复制第三方代码

本仓库目前提供自有最小可执行内核和专业Skills；**没有把Seeed、kicad-happy、Allegro exportJson的源代码拷贝进仓库**。后续需按实际许可、版本和工程环境验证后再决定集成，保留第三方NOTICE与改动记录。

### Seeed Schematic Analyzer（首选的真实OrCAD适配候选）

- [官方说明](https://github.com/Seeed-Studio/ai-skills/tree/main/skills/schematic-analyzer)
- 建议按其仓库指引安装，并使用 `pstxnet.dat + pstxprt.dat + OrCAD Capture XML` 测试overview、component、net三个查询。
- 与本仓库 `hardwarecheck inspect/component/net` 在同一组人工真值上对照，输出源文件编码、层次路径、隐藏电源脚、多单元器件情况。
- 结果合格时可由额外Adapter转换为 `docs/03-输入及数据契约.md` 的统一模型；避免同步维护两个互不兼容的解析结果。
- 不将Seeed文档中的KiCad功能推断为本环境必须安装KiCad。

### Seeed EE Datasheet Master（PDF加强）

- [官方说明](https://github.com/Seeed-Studio/ai-skills/tree/main/skills/ee-datasheet-master)
- 建议复用其“粗定位→局部搜索→表格/附近文本→必要时页面渲染→引用与交叉校验”流程。
- 本项目 `pdf-search` 仅是局部文本命中工具，不实现等价的表格参数抽取能力。
- 后续增强应加入参数结构体、条件/版本/页码、人工确认与反例测试。

### kicad-happy（方法参考）

- [官方仓库](https://github.com/aklofas/kicad-happy)
- 重点学习分层检查（确定性脚本+LLM深度审查）、可证明对象引用、隔离幻觉结果和回归样本。
- **不将KiCad的S-expression解析器当作OrCAD的解析器复用**；以设计无关的数据Schema承接方法。

### Allegro exportJson与IPC-2581

- [SKILL JSON导出工具](https://github.com/juulsA/exportJson)：目标偏向InteractiveHtmlBom，先验证对象种类、单位、网络/定位信息；如不足需新增SKILL脚本。
- IPC-2581：在本机Allegro中使用制造数据导出，记录完整输出配置。由于XML树形结构复杂，本仓库 `pcb-summary` 只清点，不实现正式IPC-2581结构化转换。
- 首批几何规则应围绕“可见位号、封装外形、位置、焊盘网络”的确证数据，先独立做对照，不要凭LLM从布局图片估量长度/距离。

## 关键接口与稳定性策略

对每个外部适配器，使用相同的内部协议：
```text
probe()      -> version/capabilities/missing dependencies
parse()      -> normalized design + warnings + provenance
query()      -> bounded component/net/subgraph response
validate()   -> checked references / unsupported cases
```

- 除非明确授权，全部为只读操作；
- 失败信息要保留，不能自动“补齐”不可靠数据；
- 记录外部项目commit、license、执行平台和输入设计版本；
- 在本地用固定数据集对比引入前后真实工程事实是否变化；
- 产品原型不默认上传任何企业设计文件。
