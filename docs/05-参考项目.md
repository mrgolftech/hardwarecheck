# 05. 参考开源项目与应用案例（核对版，2026-10-22）

> 本文件记录外部项目**公开宣称的能力、可借鉴点和风险**，不是对其在本单位OrCAD/Allegro环境成功运行的验证。依赖引入需固定版本/commit、核查许可证并完成脱敏样本验证。

## 1. 直接优先验证：OrCAD与器件手册

### A. Seeed Studio — Schematic Analyzer

- 代码/说明：https://github.com/Seeed-Studio/ai-skills/tree/main/skills/schematic-analyzer
- 文档：https://github.com/Seeed-Studio/ai-skills/blob/main/skills/schematic-analyzer/README.md
- 已公开能力：KiCad与Cadence OrCAD/Allegro逻辑网表分析，输出结构化器件、网络、页面、子系统信息，支持位号查询、网络追踪和部分接口模式检查。
- **兼容性条件**：公开文档列出的Cadence输入是 `pstxnet.dat` + `pstxprt.dat` + OrCAD Capture XML。应逐项核对字段及导出版本。
- 复用决策：**P0第一优先**；先作为只读基础能力验证，能用则不重复开发。
- 风险：XML缺失、多单元器件、层次网络别名、工具外部依赖；原生设计位置的恢复不能仅凭DAT保证。
- 许可证：Seeed `ai-skills` 仓库公开标示MIT；纳入前以具体文件/版本复核。

### B. Seeed Studio — EE Datasheet Master

- 文档：https://github.com/Seeed-Studio/ai-skills/blob/main/skills/ee-datasheet-master/README.md
- 已公开能力：电子器件PDF参数抽取，来源页码、结构化输出、表格及图表辅助分析。
- 复用决策：**P1优先结合**OrCAD Skill，建立可追溯参数缓存。
- 风险：扫描页、图形标注、极值列、温度/电压条件、型号后缀变体，必须再验证关键参数。

### C. Cadence Netlist Formatter

- 仓库：https://github.com/yuravg/cadence_netlist_format
- 已公开能力：由 `pstxnet.dat` 输出可读的网络/连接关系。
- 复用决策：Seeed完整适配失败或XML不可得时，作为轻量网表解析参考。
- 风险：公开输出侧重网络报告，不等于完整Capture层次/属性建模。

## 2. 借鉴专业审查与证据机制

### D. kicad-happy

- 仓库：https://github.com/aklofas/kicad-happy
- 方法说明：https://github.com/aklofas/kicad-happy/blob/main/how-it-works.md
- 证据机制/变更日志：https://github.com/aklofas/kicad-happy/blob/main/CHANGELOG.md
- 已公开能力：对KiCad数据以确定性Python脚本抽取，Agent按模块和器件分析设计与手册，深度审查结果须通过设计对象/引文等证据门禁；具有基于大量开源设计的回归测试流程。
- **最值得复用的不是KiCad解析代码，而是**：事实/推理解耦、per-IC审查、设计证据锚点、无效引用隔离、可重复回归。
- 风险：KiCad专用数据格式；其大规模回归测试并非对真实电路故障召回率的统计证明。

### E. KiCad MCP Pro

- 仓库：https://github.com/oaslananka/kicad-mcp-pro
- 架构：https://github.com/oaslananka/kicad-mcp-pro/blob/main/ARCHITECTURE.md
- 已公开能力：MCP工具接口，包装KiCad真实EDA功能，提供只读审查、权限分层及人工门禁等流程。
- 复用决策：**架构参考**；未来把OrCAD/Allegro工具包装为MCP时再深入。
- 风险：核心为KiCad，不能在OrCAD/Allegro直接用其操作接口。

### F. KiBot

- 仓库：https://github.com/INTI-CMNB/KiBot
- 已公开能力：KiCad设计制造资料自动生成及CI集成。
- 复用决策：借鉴EDA质量门禁、批量执行、版本化产物和可重复部署流程。
- 风险：工具核心依赖KiCad，许可证（AGPL-3.0）需要特别评估，避免照搬代码。

## 3. 重点关注Allegro的结构化数据

### G. Allegro exportJson

- 仓库：https://github.com/juulsA/exportJson
- 已公开能力：Allegro PCB Designer SKILL脚本导出用于InteractiveHtmlBom的JSON。
- 复用决策：参考Allegro SKILL对象遍历和输出方法；对于IPC-2581没有导出的所需属性，可按需编写增量提取器。
- 风险：该JSON模式围绕交互式BOM，不代表完整提供阻抗、铜皮/参考面、全部走线和设计约束。

### H. Cadence原厂IPC-2581导出（非开源）

- 官方制造数据导出说明：https://community.cadence.com/cadence_blogs_8/b/pcb/posts/ipc-2581-pcb
- 官方仅层叠数据导出说明：https://community.cadence.com/cadence_blogs_8/b/pcb/posts/exchanging-stackup-using-ipc2581
- 路线：先在实际Allegro版本中运行 `File → Export → IPC2581`，配置适合审查的制造数据、层/网络/元件属性，核验实际XML中内容。
- **注意**：Cross-section Editor导出的IPC-2581只用于层叠信息，不能把它当成全板布局布线XML。
- 风险：导出模式可裁剪数据，不同版本/许可、单位及层映射均可能影响规则可执行性。

## 4. 工业应用证明（非开源）

### I. AllSpice DRCY — Agentic Hardware Design Reviews

- 论文：https://arxiv.org/abs/2603.15672
- 官方产品方向：https://www.allspice.io/
- 价值：公开文献描述以Agent审查原理图、结合器件手册提出设计意见，为“AI语义硬件审查”提供工业应用方法参考。
- 可借鉴：功能模块分组、器件数据手册关联、将问题定位到设计对象和专家审核流程。
- 风险：**商业产品，不能照搬源代码**。论文和厂商案例不能直接证明本项目的检出率或投板成功率提升。

## 5. 推荐复用组合

| 本项目建设要素 | 借鉴对象 | 策略 |
|---|---|---|
| OrCAD网表查询 | Seeed Schematic Analyzer + Cadence Netlist Formatter | 验证后引入或适配，保留可替换接口 |
| PDF手册知识提取 | Seeed EE Datasheet Master | 仅输出带源证据的结构化参数 |
| 规则、Agent审查与报告 | kicad-happy | 方法复用；企业规则自主建模 |
| 审查工具权限和标准接口 | KiCad MCP Pro | 先Python内部接口，必要时封装MCP |
| PCB数据结构 | Allegro IPC-2581 + exportJson | 按实际导出覆盖率组合 |
| 可重复检查与验收 | KiBot + kicad-happy | 独立真值、缺陷回归、日志和对照实验 |

## 6. 引用与软件合规

- 在实现阶段创建 `third_party_inventory`，逐项记录来源URL、commit、许可证、改动、分发和相关NOTICE要求；
- 不把第三方已有算法描述成自主发明；
- 不把网上开源原理图直接替换成本单位设计的验证结论；
- 本文如需用于正式申报材料，引用到可稳定访问的仓库文档/论文并记录检索日期；
- 工程数据与客户设计不得上传公开Issue、外部CI或未经批准的模型API。
