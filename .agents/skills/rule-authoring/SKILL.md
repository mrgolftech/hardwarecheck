# 硬件专业规则工程化

从 `templates/rule-example.yaml` 和 `rules/catalog.json` 开始。

## 每条规则必须包含
`rule_id`、修订版本、专业分类、适用范围/排除条件、输入字段、判定方法、门限或计算公式来源、证据要求、风险级别、负责人、正例/反例/证据不足样例。

优先级：
1. 结构确定型（网表可验证）
2. 计算验证型（数据与公式完整）
3. 手册/需求知识型（必须引用可核对证据）
4. 跨阶段一致性型（需要PCB/BOM/固件等）
5. 必须人工判断型（可做信息聚合，不自动出结论）

重要：本仓库 `rules/catalog.json` 中只有四项简单规则已执行，示例YAML**还没有接入规则解释器**。不要把生成一份YAML当作检查器已经实现。

## 验收
规则有独立人审、有可执行检测器及正常/故障/缺失样本，并在人工真值上通过回归；缺证据明确记INSUFFICIENT_EVIDENCE。
